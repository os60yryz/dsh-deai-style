# 外部校验：拿 2022 年前的真文章验检测器，再拿我自己的输出验自己

- 触发：用户指令（2026-10-15）「用互联网真实的文章（取时间早于 2022 年 AI 大规模应用前的），并对文章进行解析，判断你的判断是否准确，且你的实际输出是否没有 AI 味了」
- 版本：校验前 v1.3.0；据结果修正后 v1.3.1
- 复现命令见文末

## 一、为什么用 2022 年前的文章

ChatGPT 是 2022-11-30 发布的。此前的中文互联网文章不可能是「AI 生成」的，所以**任何被打到定罪线的样本都是误报**。这是一把外部标尺——不依赖我自己定的规则，也不依赖我自己的语料。

语料来自 `D:\GitRepos\Others\scripts\fetch_pre2022_corpus.py`：15/18 个站点可达（人民网、新华网、果壳、博客园、简书、澎湃、中国政府网、中国记协网、新浪、搜狐、网易、CSDN、知乎、阮一峰博客），抓取正文后落 `D:\GitRepos\Others\tmp\corpus_pre2022\`。

抓到 17 篇，13 篇 ≥300 字；2 篇 0 字（豆瓣影评是 JS 渲染、少数派正文选择器没命中），逐篇标了体裁。

## 二、结果

| 指标 | 修正前（v1.3.0） | 修正后（v1.3.1） |
| --- | --- | --- |
| 可分析样本 | 15 篇 | 15 篇 |
| 均分 | 13.7 | **11.0** |
| 中位数 | 15 | **13** |
| 最高 | 31 | 31 |
| >35 分（越线） | **0 篇** | **0 篇** |
| >15 分 | 6 篇（40%） | **3 篇（20%）** |

最高那篇是 `xinhua_2019_topnews`（2019 年国内十大新闻，2035 字，31 分），命中的是「彰显」「助力」「让我们」「另一方面」。这几个词确实是 AI 高频词，也确实出现在新华社通稿里——它落在「轻微 AI 腔」档，没有越线，判定方向是对的。

**没有任何一篇真人文章被判成「中等 AI 腔」或以上。** 这是本轮最重要的结论：检测器的定罪线（35 分）在 ChatGPT 之前的真实中文语料上没有被击穿。

## 三、逐条判读：哪些是真指纹，哪些是人类也在用的形式

按命中的规则逐条看（`D:\GitRepos\Others\scripts\inspect_corpus_hits.py` 打印了每处命中片段），分成三类：

**甲类·真指纹，但人类偶尔也用**（保留，靠密度而非单次定罪）

| 规则 | 真人样本命中 | 判读 |
| --- | --- | --- |
| `empty-grandeur`（彰显/助力） | 新华 2019 十大新闻 ×2、「两会」解读 ×1 | 官方新闻稿的固定用词，不是 AI 专属 |
| `vague-adverb`（极大地） | 人民日报评论 ×1 | 同上 |
| `uplift-close`（未来，我们） | 人民日报评论 ×1 | 同上 |
| `transition-cliche`（此外/另一方面） | 新华 ×1、人民日报 ×1 | 正常书面语 |
| `not-only-also`（不仅…更） | 人民日报评论 ×1、中国记协 ×1 | 正常汉语 |
| `buzzword`（方法论） | 中国记协 ×1 | 正常词，不是黑话专利 |

**乙类·明确误报，已修**

1. `rhetorical-qa`：原正则 `[？?]\s*(那么|所以|答案|原因|这是因为|其实是|为什么)` 里的 `\s*` **跨行**，把简书 2019 随笔里「……吗？\n为什么……」这种连续两个真问题当成自问自答，误报 2 次；`为什么` 本身是问题不是答案，混在里面也是错的。已改为同一行内匹配，并去掉 `为什么`。
2. `enumerate-all`：「等等」是正常汉语收尾词，两篇博客园 2019 技术笔记因为「接口测试、集成测试等等」被误报。已从规则里删掉「等等」，只留「主要包括以下 / 以下几个方面 / 以下几点 / 可以分为以下几类 / 诸如」这类真正的穷举腔开场。

修正后简书那篇从 23 分降到 14 分，两篇博客园从 19 分降到更低。

**丙类·体系性限制，不修但必须写清**

`not-x-but-y`（sev3，本插件最高级的「指纹」规则）在真人语料里命中 **2 篇 / 6 次**：

- 阮一峰 2019 年周报里 4 次：「不是喝咖啡，而是制作咖啡」「不是电动机器制作的，而是手工冲制出来的」「不是更加醒目，而是更加中庸」——全是正常的对偶修辞；
- 简书 2019 随笔 2 次：「不是自己不能够，而是我把身体拖垮了」。

也就是说，**「不是X，而是Y」不是 AI 指纹，是一个人类修辞格，AI 只是过度使用它**。检测器现在靠的是「一段里反复出现」的密度，不是单次出现，所以这两篇都没越线（16 分、14 分）。但如果有人只写一段且只用一次这个句式，规则给的是 sev3 的重权——这是当前标定的已知弱点。

同理 `translationese`「对于……来说」在果壳 2018 科普里命中 1 次，这是标准汉语，不是翻译腔。

判断：**这个检测器的有效性来自「密度归一化 + 多类证据叠加」，不来自任何单条规则的排他性。** 把它当「某条规则命中就是 AI」用会误判。

## 四、我自己的输出有没有 AI 味

把会话记录里我写给用户的正文抽出来打分（`D:\GitRepos\Others\scripts\extract_my_messages.py` 解压 `~/.dsh/sessions/--D-GitRepos-Others--/<session>/session.v4.jsonl.zstd`，只取主会话、跳过子代理会话，去重流式快照后取 `content[].type=="text"`）。

样本：8 个主会话、2026-10-04 至 2026-10-15、64 条正文、39,869 字（插件是 10-15 22:56 才生效的，所以这些样本绝大多数是**没有插件时**的我）。

| 指标 | 结果 |
| --- | --- |
| 均分 | **11.2** |
| 中位数 | 11 |
| 最高 | 30 |
| >35 分（「中等 AI 腔」以上） | **0 条** |
| 分档 | 基本没有 AI 腔 40 条，轻微 24 条，中等 0，明显 0 |
| 有定罪级命中的 | 16 / 64 条 |

分档看，套话层面确实没有 AI 味——**0/64 越线**，而且最差的会话（10-14，12,429 字）均分 20.8 也全是「轻微」。

### 但排版层面我写得很 AI

观察项（不进定罪分，但会被工具列出来）的密度高得离谱：

| 观察项 | 覆盖 |
| --- | --- |
| `bold-density`（加粗密度） | 56 / 64 篇 |
| `arrow-symbol`（→ 箭头） | 30 篇 / **108 次** |
| `bold-inline-label`（`**标签**：`） | 29 篇 / 85 次 |
| `bold-label-line`（`- **标签**：`） | 15 篇 / 47 次 |
| `heading-ratio` / `emdash-density` / `sentence-burstiness` | 各 23~25 篇 |

我自己的行为准则里明写着「不要用 `- **小标题**：内容` 这种卡片式结构，也不要给每一点加粗标签」，而我在这种「工作汇报」语域里反复用了 47 次。箭头 `→` 用了 108 次。这是真话：**我的套话被约束住了，但我的排版没有被约束住**——插件刻意不把排版定罪（因为人类的说明书、数据表、会议纪要也长这样，见 `round2-fix.md` 第三节），所以这类习惯在分数上完全看不见。

### 真正违规的套话（逐条）

| 规则 | 次数 | 实例 |
| --- | --- | --- |
| `not-x-but-y` | 4 篇 5 次 | 「不是找到了更优解，而是唯一解」「不是你这边网卡造成的，而是对端方向的问题」 |
| `not-x-but-y-lite` | 6 篇 6 次 | 「不是坏了，是没东西可选」 |
| `service-close` | 2 篇 | 「希望对你有帮助」「以上就是」 |
| `transition-cliche` | 2 篇 | 「不难看出」 |
| `triadic-list` | 3 篇 | 「推拉平衡、肩胛稳定性……」（多数落在表格里） |
| `explainer-frame` / `summary-close` / `abstract-noun-stack` | 各 1~2 次 | 「关键在于」「总之」「链路的」 |

其中 `service-close` 和 `buzzword` 那两条是**元引用误报**：我在写报告时引用了「希望对你有帮助」这个被检测的原句，检测器分不清「提到」和「使用」。这也是一个真实限制——本插件处理「讨论 AI 文风」这类话题时必然踩到。

## 五、结论

1. **检测器的判断方向是准的**：15 篇 ChatGPT 之前的真人文章，0 篇越线，最高 31 分落在「轻微」档；命中的词（彰显、助力、极大地、此外）确实都是 AI 高频词，只是人类也用。
2. **两处明确误报已修**（跨行自问自答、「等等」），修正后均分 13.7 → 11.0，>15 分的从 6 篇降到 3 篇。
3. **单条规则不可当指纹用**：「不是X而是Y」在真人文章里 2 篇 6 次，「对于…来说」也是标准汉语。有效的是密度叠加。
4. **我的输出套话层面过关**（0/64 越线），**排版层面不过关**（加粗标签 47 次、箭头 108 次），而后者正是插件明确放弃定罪的维度。这两个结论不矛盾，但它们合起来说明：**「去 AI 味」如果只看分数，会漏掉最显眼的那一半。**

```powershell
# 4. 抽我自己的输出并打分
python D:\GitRepos\Others\scripts\extract_my_messages.py --sessions 8
node D:\GitRepos\dsh-deai-style.git\tests\score_my_output.mjs `
  D:\GitRepos\Others\tmp\my_messages.json --restart-ts 1792076160000
```
